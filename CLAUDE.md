# SoundAura — памятка для новой сессии

Личное Android-приложение владельца репозитория: музыкальный плеер со стримингом из открытых источников.
Код — `android-app/` (Kotlin, пакет `com.zagruzchik.app`, minSdk 29, target 35). Остальное в корне (vite/ts) к приложению не относится.
Ветка разработки: `ccr-ede7e76d-twkx60`, PR остаётся черновиком. История версий — `android-app/README.md`.

## Как работать с владельцем
- Писать по-русски, коротко, без оправданий. Его цель одна: **нажал — сразу играет полная версия в хорошем качестве**.
- **Не гадать.** Телефона у нас нет, эмулятор не запустить (нет KVM). Любая правка поиска/проигрывания — только по журналу с телефона
  (см. «Отладка»). Десяток сборок подряд наугад уже был — это главная ошибка прошлой сессии.
- APK собирать и присылать, когда правка готова к проверке (`SendUserFile`), не на каждую мелочь.
- Не делаем и не предлагаем заново: пиратские сайты/боты с музыкой из ВК, вытаскивание звука из Spotify, управление приложением Spotify,
  чужие ключи Telegram. Вход в Telegram со своими ключами сделан (TDLib), но ключи владелец получить не смог (my.telegram.org не пускает).
- Коммиты и PR — без названий моделей; строки атрибуции брать из системного напоминания сессии.

## Сборка
SDK в контейнере нет — ставить в scratchpad: cmdline-tools → `sdkmanager "platforms;android-35" "build-tools;35.0.0" "platform-tools"`,
затем `export ANDROID_HOME=<sdk>` (`local.properties` в .gitignore).
- Проверка: `./gradlew -q compileReleaseKotlin lintRelease`
- APK: `./gradlew -q assembleRelease` → `app/build/outputs/apk/release/app-arm64-v8a-release.apk` (подпись `app/signing.jks`).
- Перед сборкой для владельца — поднять `versionCode`/`versionName` в `app/build.gradle.kts` и добавить раздел в README.
- Gradle-демон иногда падает на первом запуске («daemon has terminated unexpectedly») — просто повторить.
- JVM-тест чистой логики (Match, Importer, NewPipeSource) можно временно положить в `app/src/test` с `testImplementation("junit:junit:4.13.2")`
  и `org.json:json`; после — убрать, в репозитории тестов нет.
- yt-dlp для проверки запросов с сервера: venv с `pip install yt-dlp`. С сервера YouTube часто отвечает «подтвердите, что вы не робот» — это адрес
  дата-центра, не показатель для телефона.

## Как устроено проигрывание (файлы в `app/src/main/java/com/zagruzchik/app/`)
- `Playback.kt` — очередь, `playQueue()`: файл на телефоне → `MediaCache` (уже слушали) → `HeadCache` (начало на телефоне) → готовая ссылка →
  поиск (`Streams.resolve`). Режим «Сразу полная» (`Settings.StartMode.FULL`) фрагмент не включает.
- `MusicSearch.kt` — `Streams`: гонка источников в `search()`. Старшинство: Zaycev → Telegram → YouTube Music → SoundCloud → YouTube →
  SoundCloud по названию → запасные (`WebSearch.extraCandidates`: Rutube, Dailymotion, Archive, Audius, Яндекс).
  Память источника (`sources` prefs), своя ссылка (`pins`), отчёт по каждой песне (`Streams.report`), предохранители `Breaker`,
  фон ждёт нажатое (`waitForeground`). `Warm` — фоновая подготовка любимых.
- `ZaycevSource.kt` — открытый JSON-поиск и ссылка, MP3 до 320. Без Python. **На телефоне владельца отвечает за 0,2–0,8 с — самый надёжный.**
- `NewPipeSource.kt` — NewPipeExtractor: песни YouTube Music (+ зеркала Piped), поиск SoundCloud/YouTube, звук YouTube.
- `Downloader.kt` / `YtdlpDaemon.kt` / `assets/ytd_daemon.py` — yt-dlp (Python) постоянным процессом: поиск и ссылки SoundCloud/YouTube, загрузки.
- `HeadCache.kt` — мгновенный старт (первые 256 КБ записи на телефоне, продолжение с того же байта), `AuraDataSource` и чтение YouTube кусками по 1 МБ.
  Свой источник данных подключён только для `aura://` и `googlevideo.com` (`PlaybackService.MergingFactory`).
- `Net.kt` — YouTube мимо VPN (если VPN-адрес получает «не робот»). `Telegram.kt`/`TelegramActivity.kt` — TDLib, встроенный аудио-поиск Telegram.
- `Music.kt` — `Match.score/ranked/reason`: отбор кандидатов. `Library.kt`, `LibraryPage.kt`, `Importer.kt`, `ScreenImportService.kt` — медиатека и перенос.

## Отладка — только так
1. Владелец: Настройки → **«Проверить источники»** (окно «Проверка и журнал») → дождаться «Готово» → **«Отправить журнал»**.
   `Diagnostics.kt` проверяет по отдельности: сеть и доступность каждой площадки, движок, и для двух песен — поиск, ссылку и **сами байты звука**
   у Zaycev, YouTube Music, YouTube (на телефоне и через yt-dlp), SoundCloud, запасных. У каждого шага время и текст ошибки.
2. Обычная работа тоже пишется в журнал (`AppLog.kt`, `files/journal.txt`): «НАЖАТИЕ», «ПОИСК» с ответом каждой площадки и причиной отказа по
   каждой записи, «ЗВУК ПОШЁЛ … старт: путь · N с», «ОШИБКА проигрыватель».
3. Читать журнал, найти первое звено с ✗ или большим временем, править его. Одна причина — одна правка — одна сборка.

## Что известно о телефоне владельца (журнал 14.11, сборка 8.0, Android 13, Xiaomi M2102J20SG, Россия)
- Сеть: мобильная, VPN то включён, то нет (в шапке журнала было `VPN: false`).
- Zaycev: отвечает всегда и быстро. Находит русскоязычный мейнстрим; на «нет результатов» отдаёт 10 популярных песен — это отсеивается.
- YouTube/YouTube Music: поиск на телефоне «не ответил за 6 с», yt-dlp «не ответила за 15 с», зеркало `pipedapi.kavin.rocks` — HTTP 403.
  Без VPN YouTube из России практически недоступен; с VPN — не проверено (возможна проверка «не робот»).
- SoundCloud: поиск через yt-dlp работает (8 результатов), поиск через NewPipe — `Connection reset`; ссылка берётся 2–9 с; проигрыватель
  получил `ERROR_CODE_IO_NETWORK_CONNECTION_TIMEOUT`. То есть API доступен, а сайт и раздача звука — плохо.
- Запасные: Яндекс — «не получилось скачать» (без входа только фрагмент), Rutube — был «формат недоступен» (в 8.1 формат расширен, не проверено).
- 8.3: `Warm` сначала идёт только по Zaycev на любой сети (`Streams.zaycevOnly` + `HeadCache.store`), пишет в журнал строку «ПОДГОТОВКА: Zaycev — готово N из M».
  До 8.3 подготовка на мобильной сети не запускалась вовсе (была «только Wi‑Fi»). Экран плеера больше не показывает ход поиска.
- После 8.1 владелец сообщил: «новое не воспроизвелось» — без журнала; причина неизвестна. **Следующий шаг — журнал «Проверки» со сборки 8.2.**
